Z.ai GLM Quota Widget Recipe

Capability

Show the authenticated Z.ai GLM Coding Plan quota windows, provider-reported usage, remaining percentage, and reset times in an active installed Baby Menu widget.

The sole quota source is GET https://api.z.ai/api/monitor/usage/quota/limit. A redacted approved probe with a zai-coding-cn API key returned HTTP 200 and two CREDIT_LIMIT records. The provider console contract identifies unit 3 as the five-hour window and unit 6 as the weekly window.

Model catalog entries, per-request prices, local Pi token totals, and model API limit errors are not account quota and must never be used as fallbacks.

Use real data only. Do not fabricate a percentage or reset when the source is missing or malformed.

This recipe is self-contained and requires no external implementation guide.

Installation and Activation

  1. Configure one explicit API-key source using the credential contract below. Restart Baby Menu after changing its launch environment.
  2. Open or reload the popover. The host invokes the visible-widget refresh and discovers zai-quota/widget.tsx and zai-quota/server.ts automatically.

Z.ai GLM quota is bundled as an active installed extension in Baby Menu. It operates through the extension system with no provider-specific core IPC or hardcoded registration in WidgetHost.

Explicit Credential Configuration

Credential reads belong only in zai-quota/server.ts. The renderer must never receive, read, persist, or submit a key.

The environment variable above is the confirmed supported non-browser API-key path. A normal GUI launch may not inherit shell-only exports, so the operator must put it in Baby Menu's actual launch environment and restart the app. Do not assume that a key saved by Pi is available to Baby Menu.

On macOS, an operator may instead create a dedicated Keychain item without placing the secret in command arguments or shell history. Run this command and enter the key only at the secure prompt:

/usr/bin/security add-generic-password -U \
  -a zai-coding-cn \
  -s com.kunchenguid.baby-menu.zai-quota \
  -w

Use /usr/bin/security find-generic-password -s com.kunchenguid.baby-menu.zai-quota -a <account> -w from the server action with an argument array, shell: false, ignored stdin, a five-second timeout, and bounded stdout. Hold stdout only in memory and discard it after constructing the request.

Do not pass the key after -w, put it in source, write it to SQLite, forward it through window.babyMenu, or print command output. If no explicit environment or dedicated Keychain source exists, return authentication-required before any network request.

Exact Provider Request

GET https://api.z.ai/api/monitor/usage/quota/limit
Authorization: Bearer <explicit API key>
  • Use exactly this HTTPS origin and path with no query string.
  • Set method: "GET", redirect: "error", and one 15-second whole-request abort deadline.
  • Set only the required Authorization header. Do not add cookies, organization/project guesses, browser headers, referrers, content headers, or a request body.
  • Do not send prompts, source code, paths, logs, project metadata, personal data, account identifiers, or any other Baby Menu content.
  • Apply a 64 KiB streamed response cap before JSON parsing. Do not retry automatically.

Verified Response Contract

The successful envelope has data.limits[]. Parse only the allowlisted fields below. Unknown top-level, envelope, limit, and detail fields are discarded rather than copied into renderer state or cache.

Provider fieldValidation and normalized meaning
typeRequired bounded provider identifier. Preserve it exactly. CREDIT_LIMIT is the confirmed credit-window type.
unitRequired non-negative integer. Preserve it exactly. Only CREDIT_LIMIT + 3 and CREDIT_LIMIT + 6 receive semantic labels.
percentageOptional finite number in 0..100, confirmed by the provider UI as percent used. Preserve it as percentage; derive percentRemaining = 100 - percentage only when present.
currentValueOptional finite non-negative number or bounded numeric string. Preserve the value without inventing a semantic name or coercing a missing value.
usageOptional finite non-negative number or bounded numeric string. Preserve the value without using it to manufacture a percentage.
nextResetTimeOptional valid provider date string or epoch-millisecond number. Preserve the validated scalar and also normalize it to ISO 8601 as resetAt. Reject epoch-second guesses. Never substitute now, zero, or an elapsed-time estimate.
usageDetails[].modelCodeOptional bounded model identifier confirmed by the provider console. Preserve the code; do not guess a display name.
usageDetails[].usageOptional finite non-negative number or bounded numeric string confirmed by the provider console. Preserve only this value.

Unit 3 means 5-hour only when type === "CREDIT_LIMIT". Unit 6 means Weekly only with that same type. An unknown type or unit may remain visible as its literal provider type and unit, but must not inherit one of these labels.

Missing or null optional fields stay absent. Do not turn them into zero, an empty detail, or a reset. A present field with an incompatible type, invalid percentage, invalid date, malformed detail array, missing required type/unit, empty limits array, or missing data.limits is malformed-response.

Normalized Types

type ZaiQuotaWindow = {
  id: string;                         // `${type}:${unit}`
  label?: "5-hour" | "Weekly";       // only CREDIT_LIMIT units 3 and 6
  type: string;
  unit: number;
  percentage?: number;                // provider percent USED
  percentRemaining?: number;          // 100 - percentage, only when reported
  currentValue?: number | string;
  usage?: number | string;
  nextResetTime?: string | number;    // validated provider scalar
  resetAt?: string;                   // normalized ISO 8601
  usageDetails?: Array<{
    modelCode?: string;
    usage?: number | string;
  }>;
};

type ZaiQuotaSnapshot = {
  schemaVersion: 1;
  source: "zai-quota-api";
  endpoint: "https://api.z.ai/api/monitor/usage/quota/limit";
  credentialSource: "zai-coding-cn-env" | "baby-menu-keychain";
  windows: ZaiQuotaWindow[];
  refreshedAt: string;
  stale: boolean;
};

type ZaiQuotaFailure = {
  status:
    | "authentication-required"
    | "rate-limit"
    | "service-error"
    | "malformed-response"
    | "unavailable";
  message: string;                     // fixed safe copy only
  httpStatus?: number;                 // safe status only
  retryAt?: string;                    // parsed Retry-After only
  diagnostic?: "timeout" | "network" | "response-too-large";
};

type ZaiQuotaResult =
  | {
      ok: true;
      status: "fresh" | "stale";
      checkedAt: string;
      data: ZaiQuotaSnapshot;
      warning?: ZaiQuotaFailure;
    }
  | ({ ok: false; checkedAt: string } & ZaiQuotaFailure);

type ZaiQuotaViewState =
  | { status: "loading"; previous?: ZaiQuotaResult }
  | { status: "settled"; result: ZaiQuotaResult };

Loading is renderer state, not a fabricated server response. During a later refresh, retain a prior fresh or stale snapshot and add an updating indicator instead of replacing it with an empty loading view.

Implementation Contract

Create zai-quota/server.ts, store.ts, components.tsx, and widget.tsx. Components exports React components only; store owns state and refresh; widget exports the descriptor.

All credential, Keychain, network, response-bound, JSON, parser, and cache work belongs in server.ts. Expose only actions.getQuota and invoke it as window.babyMenu.capabilities.invoke("zai-quota", "getQuota").

Server action response shape is ZaiQuotaResult. It contains normalized non-secret values only.

Single-flight the complete acquisition. Use an extension-scoped module variable named like zaiQuotaLastGoodCache for one in-memory normalized snapshot. Guard reuse with a process-local keyed digest of the exact credential and safe credential source; never return, log, or persist the digest. A changed credential cannot reuse the previous snapshot.

Do not persist a last-good row because this endpoint does not return a confirmed safe principal for cross-restart cache binding. If a future provider contract supplies one, any durable table must be extension-prefixed, such as zai_quota_cache, and may contain only normalized quota/reset/freshness/source status. It must never contain a key, credential digest, account field, or raw response.

Only a successful exact-source response updates last-good data. Eligible timeout, network, rate-limit, 5xx, incompatible JSON, and malformed-shape failures may return the same-credential snapshot as status: "stale", with its original refreshedAt, stale: true, and a safe structured warning. Missing or rejected credentials never render stale data.

Renderer and Refresh Contract

Export a RefreshableBabyMenuWidget with viewRefreshIntervalMs: 600_000 and a shared refreshView. Ten minutes matches the provider's observed quota freshness and is the slowest acceptable visible cadence.

The host call is the startup/open refresh. Do not issue a mount-time request, start a timer, or add a background task. Quota is needed when the popover is visible, not while it is closed.

Render a compact 504px popover body using @babymenu/ui, token Tailwind classes, Progress, StatusDot, and Skeleton. Do not add a card background, gradient, custom palette, emoji, or a second accent.

  • Use Z.AI · GLM as the tracked-caps key.
  • For each reported window, show remaining percentage as the primary value and feed that same remaining value to a meter labeled remaining. Show provider percentage separately as percent used.
  • Show -- rather than zero when percentage or reset is absent.
  • Show reset only from valid resetAt. Round display values only; keep exact values in state.
  • Loading shows a quiet skeleton. Updating keeps last-good values visible. Fresh uses a mint status dot; stale uses amber and visibly says cached/stale.
  • Authentication-required copy names the supported environment/Keychain setup. Rate-limit, service-error, malformed-response, and unavailable each use distinct accurate copy.
  • Never put credentials, account fields, raw provider values outside the allowlist, raw JSON, headers, exception text, or credential digests in the DOM.

Privacy and Security Constraints

  • The quota GET carries no project or personal content. It contains only the explicit Z.ai bearer required for authentication.
  • Never scrape browser cookies/localStorage, use withCredentials, inspect a browser profile, or launch a browser login.
  • Never read Pi's or another tool's private auth store by assumption. Requiring explicit operator configuration is safer than silently borrowing an identity.
  • Never persist or print API keys, key fragments, credential digests, browser state, account ids, emails, headers, raw JSON, provider error text, or a raw provider response.
  • Discard all response fields except the normalized allowlist. Do not send provider data to telemetry or another model.
  • Do not send personal data to GLM/Z.ai. This quota operation needs no source code, prompt, filename, path, log, or project metadata.

Low-risk Live Verification

  1. Verify only that an explicit environment variable or the dedicated Keychain item is present. Do not print its value, length, prefix, hash, or source command output.
  2. Invoke zai-quota.getQuota once against the fixed endpoint. Capture the body only in bounded process memory.
  3. Print or record only a fixed status classification, the safe source id, whether CREDIT_LIMIT:3 and CREDIT_LIMIT:6 were present, and whether each had a valid percentage/reset. Do not print raw JSON, account fields, provider errors, or credential material.
  4. Open the popover and compare the normalized 5-hour and weekly values and resets to the same in-memory action result. Leave no payload, screenshot containing account data, credential file, or diagnostic dump behind.
  5. If no explicit credential is configured, stop at authentication-required. Do not fall back to Pi or browser state to make the check pass.

Acceptance Criteria

  • The implementation is an active installed zai-quota extension in Baby Menu.
  • The server action uses only the exact GET, fixed endpoint, required bearer header, no body, no redirect, a timeout, and a response cap.
  • Credential resolution uses only the explicit Z.ai environment variable or the dedicated Baby Menu Keychain item and never reads Pi/browser state.
  • Tests execute the generated server action and cover valid unit 3/6 windows, missing optional fields, malformed fields/envelopes, reset parsing, missing credential, HTTP 401/403, HTTP 429, HTTP 5xx, unavailable/network outcomes, same-credential stale cache, and credential-change cache rejection.
  • Behavioral request tests prove there is no query, body, cookie, browser header, guessed organization header, or project/personal content.
  • Boundary tests prove secrets, unknown account fields, raw provider fields, raw failures, and raw responses do not appear in results, logs, the DOM, or durable SQLite state.
  • Loading, updating, fresh, stale, authentication-required, rate-limit, service-error, malformed-response, and unavailable states remain distinct and never replace missing data with zero or a fabricated reset.
  • The widget refreshes only while visible, no faster than every ten minutes, with no extension-owned timer or background task.
  • A redacted live check reports only safe classifications and field presence. It never emits credentials or provider payloads.
