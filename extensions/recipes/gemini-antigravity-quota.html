Gemini via Antigravity Quota Widget Recipe

Capability

Track Gemini quota from the installed Antigravity CLI for a Baby Menu widget.

Use only Antigravity's provider-owned, read-only /usage command. Do not read Antigravity credentials, call an inferred private endpoint, derive windows from token counts, or fabricate a fallback.

Scope: this recipe defines acquisition, normalization, stale behavior, and security. The generated widget chooses its compact Baby Menu presentation.

This recipe is self-contained. Do not require external source code, websites, or implementation guides to complete it.

Recommended Data Source Order

PrioritySourceUse whenExpected data
1 Antigravity CLI /usage agy is installed and Antigravity owns a signed-in session. Provider-defined quota groups and buckets, remaining fractions, window labels, and reset times.
2 Cached last-good normalized snapshot The provider command is temporarily unavailable and a previous successful snapshot exists. The same normalized data marked stale, never invented data.

There is no credential-file, browser-storage, direct-API, token-count, or alternate-CLI fallback. Do not install or invoke quota-axi.

Verified Antigravity CLI Contract

The installed CLI exposes the provider-owned usage command in non-interactive structured output. The minimal verified form is agy --output-format stream-json --print='/usage'.

The server action must suppress account decoration and provider logs while retaining Antigravity's own authenticated session:

AGY_CLI_HIDE_ACCOUNT_INFO=1 agy \
  --output-format stream-json \
  --log-file /dev/null \
  --print='/usage'
  • Run with the extension workspace as cwd. Do not pass --new-project, --add-dir, a prompt for a model turn, or any permission-bypass flag; /usage is a read-only local command.
  • Use a hard 15-second timeout, cap stdout and stderr independently at 1 MiB, close stdin immediately, and terminate the child on timeout or overflow.
  • Never return or log raw stdout or stderr. Diagnostics may include only a safe failure kind, exit status, and byte counts.

A successful stream contains an event with event: "command_result", followed by a duplicate summary in the terminal result event. From the first event with that discriminator, parse command.data.groups and ignore the duplicate terminal copy.

type AntigravityUsageCommand = {
  event: "command_result";
  command: {
    name: "usage";
    data: {
      description?: string;
      groups: Array<{
        name: string;
        description?: string;
        buckets: Array<{
          id: string;
          name: string;
          description?: string;
          window: string;
          remaining_fraction: number;
          reset_time: string;
        }>;
      }>;
    };
  };
};

This shape was verified from the real installed agy command with output redacted during inspection. Treat live structured output as canonical and reject incompatible shapes rather than guessing.

Normalization Contract

Always preserve the provider-reported group, bucket, and window labels. Do not infer, rename, or synthesize quota windows. In particular, do not convert a window label into a five-hour, daily, weekly, or monthly claim unless Antigravity reports that exact label.

  • Require non-empty group names and bucket id, name, and window strings.
  • Require remaining_fraction to be finite and in the inclusive range 0..1. Convert it to percentRemaining = remaining_fraction * 100. Do not reinterpret it as percent used.
  • Accept reset_time only when it parses as a valid timestamp; otherwise omit resetAt while keeping an otherwise valid bucket.
  • Ignore description fields in the renderer-facing result because provider prose can change and is not needed to track quota.
  • If no valid buckets remain, return a parser-incompatible result rather than an empty successful quota.
type GeminiQuotaSnapshot = {
  source: "antigravity-cli";
  groups: Array<{
    name: string;
    buckets: Array<{
      id: string;
      name: string;
      window: string;
      percentRemaining: number;
      resetAt?: string;
    }>;
  }>;
  refreshedAt: string;
  stale: boolean;
};

type GeminiQuotaFailure = {
  kind: "cli_not_found" | "sign_in_required" | "timeout" | "provider_unavailable" | "parse_incompatible";
  message: string;
};

type QuotaResult<T> =
  | { ok: true; data: T; warning?: GeminiQuotaFailure }
  | { ok: false; checkedAt: string; failure: GeminiQuotaFailure; sourceTried: ["antigravity-cli"] };

Implementation Contract

Put process spawning, parsing, timeout handling, and caching in gemini-antigravity-quota/server.ts. Expose actions.getQuota, and call it only through window.babyMenu.capabilities.invoke("gemini-antigravity-quota", "getQuota", input). Do not add preload methods or provider-specific IPC.

Persist only the normalized last-good snapshot in an extension-prefixed table through context.db. Never persist command output. On a transient launch, timeout, service, or parse failure, return the last-good snapshot with stale: true and a structured warning; without a cache, return the explicit failure.

Use refreshView for refresh on popover open and viewRefreshIntervalMs: 300000 while visible. Do not add a background task unless the user explicitly asks for closed-popover monitoring.

Before writing parsing code, run the exact real command above with stdout redirected to a temporary file, inspect only redacted structure and field types, and delete the file. Before reporting done, invoke the finished server action against that same real command and compare normalized bucket counts and ranges without printing names, account details, raw output, or live quota values.

Server action response shape is the QuotaResult<GeminiQuotaSnapshot> union above.

Error Handling

  • ENOENT means cli_not_found: show that the Antigravity CLI is unavailable and ask the user to install agy.
  • A structured result.status: "ERROR" whose safe classification indicates authentication means sign_in_required: ask the user to open Antigravity and sign in. Never forward result.error.
  • Timeout, non-authentication nonzero exit, or interrupted output means provider_unavailable (or timeout) and should prefer stale last-good data.
  • Malformed JSON, a missing usage command result, invalid groups, or no valid buckets means parse_incompatible and should prefer stale last-good data.
  • Never turn per-turn token usage into subscription quota and never infer reset windows.

Security Constraints

  • Filesystem and shell access belongs only in the extension server action.
  • Authentication stays provider-owned. Do not inspect, copy, parse, refresh, or send Antigravity credentials anywhere.
  • The renderer receives only normalized names, window labels, percentages, reset times, freshness, and safe failure kinds.
  • No account identifiers, raw command output, credential material, local paths, or provider diagnostics may enter logs, cache rows, fixtures, screenshots, or committed files.

Acceptance Criteria

  • The server action uses only Antigravity's structured /usage command and never reads credentials or calls an inferred endpoint.
  • Every displayed group, bucket, window, remaining percentage, and reset comes from validated provider fields without invented windows.
  • Missing CLI, sign-in, timeout, provider, and parser failures are distinct and never expose raw output.
  • Last-good normalized data remains visible and marked stale during transient failures.
  • Refresh runs no faster than every five minutes and pauses with the hidden popover.
  • The implementation has no separate quota helper dependency.
  • Live verification compares only redacted structure and normalized ranges, leaving no sensitive artifact behind.
